DIME 算法与训练框架详解（基于 diffusion-rl / DIME 项目代码）

从训练主循环到 Actor/Critic 结构，再到 Env-Buffer-网络之间的数据流，做一份“能直接对照代码阅读”的可视化说明。
参考核心文件：run_dime.py、run_multiagent_dime.py、diffusion/dime.py、diffusion/diffusion_policy.py、models/critic.py

1) 项目使用的算法是什么？

算法名：DIME 范式：Diffusion + Maximum Entropy RL 实现框架：JAX + Flax + SB3 Off-Policy

核心思想

  • 把策略（Actor）做成扩散采样器：从先验噪声逐步积分，最终得到动作。
  • Critic 不是单值 Q，而是“分布式 Q”（每个动作输出价值分布原子概率）。
  • 在 actor 目标里，不仅有 -Q，还有扩散路径相关代价（running / stochastic / terminal costs）。
  • 温度系数 alpha（ent_coef）自动学习，用来平衡“利用价值”和“保持策略熵”。

与常见 SAC 的关系

  • 依然是离策略（off-policy）：环境采样到 Replay Buffer，再做批量梯度更新。
  • 仍有双 Q（n_critics=2）与目标网络软更新。
  • 不同点在于：策略不是高斯 MLP 直接出动作，而是扩散过程采样动作。
  • 不同点在于：Critic 采用 n_atoms=101 的分布式表示而非标量回归。
默认批大小
256
UTD（每轮梯度步）
2

16

2) 训练总框架图（Actor / Critic / Env / ReplayBuffer 关系）

图示对应 run_dime.py + diffusion/dime.py 的核心数据流。单智能体使用 SB3 的 off-policy 主循环；多智能体版在 run_multiagent_dime.py 里手写 env step 循环，但更新逻辑仍复用 DIME。

训练主循环（单智能体）

  1. 从环境拿到观测 s，Actor 采样动作 a（学习初期可随机探索）。
  2. 执行 env.step(a) 得到 (s', r, done)。
  3. 转移存入 Replay Buffer。
  4. 当 learning_starts 且 buffer 足够大时，按 utd 做多步梯度更新。
  5. Critic 每步更新；Actor 按 policy_delay 间隔更新。
  6. 定期保存参数并写日志到 TensorBoard/WandB。

关键损失（代码等价表达）

Actor:
L_actor = E[ -min(Q1, Q2) + α * (run_cost + sto_cost + terminal_cost) ]

Critic:
1) 用 target_actor 采样 next_action 及 next_costs
2) 计算分布式 target（投影到 [v_min, v_max] 的 n_atoms 原子）
3) 当前 Q 分布 vs target 分布做交叉熵 + 熵正则

Temperature:
α 自动优化（ent_coef_state），用于平衡价值项与熵项

3) Actor 网络结构与输入输出

和你图一最大的差别：DIME 里的 Actor 不是“MLP 直接输出 mean / variance，然后 reparameterize 采样”的高斯策略。 它真正输出的是每个扩散步里的 forward drift / score correction，再通过 EM 积分把 latent 从 x_t 逐步推进到 x_T，最后再经过 tanh 得到动作。
这张细化图对应 diffusion/common/models/pisgrad_net.py、diffusion/od/dis.py、diffusion/od/od_integrators.py 和 diffusion/od/od_sampling.py。 如果你更习惯高斯 Actor 的画法，可以把这里的 state_time_net 理解成“在每个扩散步上输出一个修正量”，而不是一次性输出 μ 和 σ。

Actor 内部子模块逐层拆解

模块 实际结构 输入 输出
Fourier 时间编码 sin/cos((coeff * t) + phase) t 时间特征
time_coder_state Dense(256) -> GELU -> Dense(256) 时间特征 t_net1
state_time_net (Dense(256) -> GELU) x 3 -> Dense(act_dim) [x_t, obs, t_net1] out_state
time_coder_grad Dense(256) -> (GELU -> Dense(256)) x 3 -> Dense(act_dim) 时间特征 t_net2
可选 target-score 注入 out_state + t_net2 * target_score out_state, t_net2, target_score 最终 actor 输出
EM 单步采样 x_(t+1) ~ N(fwd_mean, 2 * eta * I) x_t, prior drift, actor 输出 x_(t+1)

如果按你图一的风格去对应

高斯 Actor（你图一）:
obs -> MLP -> mean / variance -> resample -> action

DIME Actor（这个项目）:
obs + x_t + t -> PISGRADNet -> 单步 drift correction
                 -> EM 积分推进 x_t -> x_(t+1)
                 -> 重复 T 次
                 -> tanh(x_T) -> action

所以：
- “mean / variance” 那一层，在 DIME 里并不存在
- 真正可视化重点应放在：
  1) 条件输入 obs
  2) 时间编码 t
  3) latent 状态 x_t
  4) 每一步的 drift / score 修正
  5) 多步积分后的最终动作

Actor 输入/输出汇总

项 形状（示意） 来源 用途
observation [B, obs_dim] 环境或 replay batch 条件输入（condition）
z0 [B, act_dim] prior sampler 扩散初始 latent
time step t [B, 1] 积分循环 时间嵌入与动态更新
action [B, act_dim] 扩散终态 tanh 后 与 env 交互、送入 critic
run/sto/terminal costs [B] 采样轨迹统计 熵项与训练目标

Actor 相关目标函数

在 update_actor 中（dime.py）：

qf_pi1 = sum(q_dist1 * z_atoms)
qf_pi2 = sum(q_dist2 * z_atoms)
min_qf = reduce([qf_pi1, qf_pi2])

L_actor = mean(
  -min_qf
  + alpha * (run_cost + sto_cost + terminal_cost)
)

说明：
- alpha 来自可学习的温度系数 ent_coef_state
- run/sto/terminal costs 是扩散策略的“熵/路径代价代理项”

Critic 输入/输出与默认结构

项 默认配置 代码位置
输入 [obs, action] 拼接 models/critic.py / Critic.__call__
隐藏层 [2048, 2048] configs/alg/dime.yaml

输出 n_atoms = 101 概率分布 softmax over atoms
标量 Q sum(prob * z_atoms) dime.py / update_actor

Critic 目标分布（简化）

z_atoms = linspace(v_min, v_max, n_atoms)

next_action 由 target_actor 采样得到
next_cost = next_run + next_sto + next_terminal

entropy_bonus = -(1-done) * gamma * alpha * next_cost
target_z = clip(
  reward + entropy_bonus + (1-done) * gamma * z_atoms,
  v_min, v_max
)

将 target_z 投影到离散原子上，得到 projected_target_dist
对当前 critic 的分布输出做交叉熵损失

5) 多智能体训练框架（run_multiagent_dime.py）

流程差异

  • 环境是多智能体 dict 形式：每个 agent 都有独立 obs/action/reward/done。
  • 动作采样是“共享一套 DIME 参数，对每个 agent 逐个调用 predict”。
  • 每次 env.step 后，把每个 agent 的 transition 都写入同一个 replay buffer。
  • 训练触发条件仍是 buffer 大小 + learning_starts，与单智能体一致。
  • num_timesteps 按 env step 计数，同时另外记录 total_agent_steps。

你可以这样理解

“多智能体版本 = 数据采集层改成 MA，
参数更新层仍是同一个 DIME 算法内核”。

也就是：
MA env -> (多条 agent transition) -> shared replay buffer
        -> shared actor/critic update (JAX 批训练)
重要说明：这个多智能体实现并不是 centralized critic。 它更接近“参数共享的独立学习”：先从多智能体环境中提取单个 agent 的观测空间和动作空间，然后所有 agent 共享同一套 Actor/Critic 参数； 每个 agent 的 transition 被分别写入同一个 replay buffer，再按单智能体 DIME 的方式训练。

Algorithm: Multi-Agent DIME with Shared Parameters

根据 run_multiagent_dime.py 与 diffusion/dime.py 整理，风格上参考你给的论文伪代码图。
1:
Initialize shared diffusion actor π_φ, shared critics Q_θ1, Q_θ2, target actor π̄, temperature α.
2:
Initialize replay buffer D.
3:
Reset multi-agent env and get initial observation dict O = {o_i}.
4:
while env_steps < total_timesteps do
5:
if no active agents remain then reset env with next seed and continue
6:
for each agent i in active agent set A do
7:
if env_steps < learning_starts then sample random action a_i
8:
else sample a_i ~ π_φ(. | o_i) with current DIME actor
9:
end for
10:
Execute one joint environment step with action dict A_t = {a_i}.
11:
Observe O' = {o'_i}, rewards R = {r_i}, terminations T = {done_i}, truncations U = {trunc_i}.
12:
for each agent i in previous active set A do
13:
Set d_i = done_i or trunc_i.
14:
if next obs o'_i is missing then use zero tensor with same shape as o_i.
15:
Store single-agent transition (o_i, a_i, r_i, o'_i, d_i) into shared buffer D.
16:
end for
17:
Increment env_steps; set model.num_timesteps = env_steps.
18:
if env_steps >= learning_starts and |D| >= batch_size and training condition is satisfied then
19:
repeat gradient_steps = utd times
20:
Sample mini-batch B = {(s, a, r, s', d)} from D.
21:
Sample next actions a' ~ π̄(. | s') using target diffusion actor.
22:
Compute projected distributional target with reward, γ, and entropy-related diffusion costs.
23:
Update critics Q_θ1, Q_θ2 by cross-entropy loss on atom distributions.
24:
Soft-update target critics with coefficient τ.
25:
if current update index satisfies policy_delay then
26:
Sample current actions a ~ π_φ(. | s) and corresponding diffusion costs.
27:
Update actor by minimizing -min(Q1,Q2) + α(run_cost + sto_cost + terminal_cost).
28:
Update temperature α.
29:
Soft-update target actor with coefficient policy_tau.
30:
end if
31:
end repeat
32:
end if
33:
if global episode termination __all__ is true then log episode metrics and reset env
34:
else set O = O'
35:
end while
36:
Save final actor/critic checkpoints.

这个伪代码和单智能体版相比的本质变化

  • 采样阶段从“一个 obs -> 一个 action”变成“一个 obs_dict -> 一个 action_dict”。
  • 存储阶段从“一条 transition”变成“每个 agent 各写一条 transition”。
  • 训练阶段没有改成 joint-action critic，而是仍然按单 agent 样本做共享参数训练。
  • 因此更准确的名字是：parameter-sharing multi-agent DIME。

多智能体环境

   -> 共享 Actor π_φ 分别产生 a_i
