Overview

DIME 在这个项目里到底是什么

从实现上看，DIME 可以理解为“把 SAC 这一类离策略最大熵强化学习的策略部分改造成扩散采样器”， 同时把 critic 改成分布式 Q（categorical distributional critic）。因此它保留了 env -> replay buffer -> sample batch -> update 这条典型离策略训练主线， 但 actor 的动作生成方式和熵正则的表达方式都和传统高斯策略不同。

核心思想 1

外层训练循环仍然是离策略 RL

单智能体入口 run_dime.py 直接调用 model.learn(...)；也就是环境交互、buffer 存储、何时触发训练， 仍然沿用 SB3 的 OffPolicyAlgorithm 思路。

核心思想 2

Actor 不是输出均值方差，而是“采样一个动作”

实现里没有单独的 class Actor。actor 由 DiffPol + DiffusionModel + PISGRADNet + Sampler 共同组成， 输入状态后通过多步扩散积分采样出最终动作。

核心思想 3

Critic 学的是回报分布，不是单个标量

VectorCritic 默认并行 2 个 critic，每个 critic 输出 101 个 atom 的概率分布，最终的标量 Q 通过 Q = Σ p(z_i) z_i 得到。

一个很重要的实现层理解： DIME 的“最大熵”不是像普通 SAC 那样直接写成 -alpha * log pi(a|s)， 而是通过扩散采样过程中产生的 running_cost / stochastic_cost / terminal_cost 来构造 actor loss 和 critic target。

单智能体

外层由 SB3 负责 roll-out

run_dime.py 创建真实环境后直接调用 DIME.learn(total_timesteps=...)。 也就是说，单智能体路径里环境交互、buffer 写入、何时触发训练，都走 OffPolicyAlgorithm 的标准流程，DIME 主要接管的是 “train 时怎么更新 actor / critic”。

多智能体

外层由 run_multiagent_dime.py 手写循环

多智能体环境不直接交给 SB3，而是手动执行 obs -> action dict -> env.step(actions)。 之后把每个 agent 的 transition 分别写入同一个 replay buffer， 训练核心仍然复用同一个 DIME.train()。

Training Loop

训练过程拆解：每次真正更新参数时发生了什么

这部分对应源码里的 diffusion/dime.py。 外层收集数据以后，真正的训练核心是 train() 和 JIT 编译后的 _train()。后者会在一个 batch 上重复若干次 gradient_steps。

Step 1

Critic update

  • 从 replay buffer 取出 (s, a, r, s', done)。
  • 用 target_actor 在 s' 上采样 a'。
  • 得到扩散路径上的 running/stochastic/terminal costs。
  • 用分布投影构造目标分布，再和当前 critic 分布做 BCE。
Step 2

Actor update

  • online actor 在当前 s 上采样动作。
  • critic 计算该动作的两个 Q 分布并转成期望 Q。
  • 取双 Q 的 reduce 结果作为价值项。
  • 目标是最大化 Q，同时惩罚扩散采样成本。
Step 3

温度与目标网络

  • critic 更新后执行 soft_update(tau)。
  • 命中 policy_delay 时才更新 actor。
  • 随后更新 entropy coefficient alpha。
  • 最后用 policy_tau 同步 target actor。
for each environment interaction: collect transition and push into replay buffer if enough data: sample batch_size * gradient_steps transitions for i in range(gradient_steps): critic <- update_critic( batch, target_actor, target_critic_or_crossq_path, alpha, z_atoms ) target_critic <- soft_update(critic, tau) if current_step hits policy_delay: actor <- update_actor(batch.obs, critic, alpha) alpha <- update_temperature(run_costs_proxy) target_actor <- soft_update(actor, policy_tau)

Critic target 的直观解释

对每个 next state，DIME 不是像普通 SAC 一样只看 r + gamma * Q(s', a')， 而是把扩散采样器返回的成本项也带进去：

target_z = clip( reward - gamma * alpha * (running_cost + stochastic_cost + terminal_cost) + gamma * support_z, v_min, v_max )

这里的写法是源码含义的直观化表达。真实实现里会先做分布投影，再对两个 critic 的目标分布取平均。

源码级实现细节

  • crossq_style=True，critic 更新里会把当前和下一时刻样本拼接后一起过网络。
  • target_entropy 在代码中直接设成 action_dim * 4.0。
  • 配置里的 alg.ent_coef.target 并没有在当前实现中真正用于温度更新。
  • update_temperature() 使用的是 run_costs 这一项作为更新信号，而不是三项成本之和。
  • tau 和 policy_tau 分别对应 critic target 和 actor target。
Actor

Actor 结构：DiffPol + DIS sampler + PISGRADNet

这个项目里最容易误解的一点是：actor 并不是一个简单的 MLP。 从代码组织上看，actor 是一个“组合体”。DiffPol 负责把策略包装成 SB3/JAX 可调用对象，真正决定每一步扩散更新方向的是 PISGRADNet，真正把动作采样出来的是 DIS + EM integrator。

Actor 输入 / 输出总结

项目 含义 源码位置
obs 环境观测；若是 dict 观测，会先 flatten/拼接后再进入网络。 DiffPol.build() / DIME.train()
x_t 扩散过程当前的 latent，维度通常与 action dim 一致。 PISGRADNet.__call__()
t 扩散步编号，会被编码成 Fourier 特征。 PISGRADNet.get_fourier_features()
output action 最终经过 tanh 压缩后的连续动作。 od_sampling.single_sample()
costs running / stochastic / terminal 三类成本，用于 actor loss 与 critic target。 DiffPol.sample_action()

为什么说源码里“没有单独的 Actor 类”

  • DiffPol 负责策略接口与状态管理。
  • init_dis() 构造 DiffusionModel 及其参数。
  • init_model() 真正实例化 PISGRADNet 并生成 TrainState。
  • sample_od() 才是“把状态变成动作”的实际执行过程。
  • 所以 actor 更像“一个带有扩散动力学的策略系统”，而不是单一模块。
Critic

Critic 结构：VectorCritic + Distributional Q

critic 这一边比 actor 更接近传统离策略 RL，但有两个明显变化： 第一，它默认是双 Q；第二，它不是回归一个标量，而是输出一个离散 support 上的概率分布。

Critic 输入 / 输出总结

项目 说明 默认配置
obs 状态向量，dict 观测在训练阶段会先被拼接。 取决于环境
action 连续动作向量。 取决于环境
hidden sizes 每个 critic 的隐藏层宽度。 [2048, 2048]
n_critics 并行 critic 数量。 2
n_atoms 每个 critic 输出的分类 support 数。 101
output shape 原始输出是分布，不是标量。 [2, B, 101]

Actor 与 Critic 的分工边界

  • actor 负责“给定状态如何采样动作”。
  • critic 负责“给定状态与动作，这个动作值不值”。
  • actor 不直接输出 log-prob，而是输出扩散路径成本。
  • critic 不直接输出一个 Q 标量，而是先输出离散回报分布。
  • 两者的耦合点发生在 update_actor() 和 update_critic() 内部。
Single vs Multi-Agent

单智能体与多智能体训练路径有什么不同

项目里有两条入口：run_dime.py 和 run_multiagent_dime.py。它们的核心训练算法相同，但外层采样方式不同。

run_dime.py

单智能体

  • 通过 create_env() 创建真实环境。
  • DIME 直接持有这个 env。
  • 调用 model.learn(...)，由 SB3 负责 roll-out。
  • 适合 gym / dm_control / 单智能体 MetaDrive。
run_multiagent_dime.py

多智能体

  • 真实环境由 create_multiagent_env() 创建。
  • DIME 挂的是一个只提供空间定义的 _SpaceOnlyEnv。
  • 实际 roll-out 在 _train_multiagent() 中手写。
  • 每个 agent 的 transition 都会被写进同一个 replay buffer。

这意味着什么

  • 算法核心没有变，变的是“谁来驱动环境和收集数据”。
  • 多智能体版本里，env_steps 按环境步数计数，但每一步可能向 buffer 写入多个 agent transition。
  • 也就是说，多智能体情况下“环境步数”和“训练样本数”不是 1:1 的关系。
Source Map

看源码时该从哪些文件入手

如果你后面还想继续深入读这个项目，建议按下面的顺序看。这样能最快把“配置 → 训练入口 → 策略 → critic → sampler” 串起来。

训练入口与环境

  • run_dime.py：单智能体训练入口。
  • run_multiagent_dime.py：多智能体训练入口与手写 roll-out。
  • common/env_factory.py：单智能体环境创建。
  • common/multiagent_env_factory.py：多智能体环境创建。

算法主干

  • diffusion/dime.py：train / update_actor / update_critic / 温度更新。
  • common/off_policy_algorithm.py：JAX 版本离策略算法底座。
  • common/type_aliases.py：critic train state 里 target params 的定义。

Actor 相关

  • diffusion/diffusion_policy.py：把 actor/critic 组装成策略。
  • diffusion/od/dis.py：构造 DIS 类型 diffusion model。
  • diffusion/od/od_sampling.py：真正的动作采样。
  • diffusion/od/od_integrators.py：Euler-Maruyama 积分器。
  • diffusion/common/init_diffusion_model.py：初始化 PISGRADNet 与 actor TrainState。
  • diffusion/common/models/pisgrad_net.py：单步扩散网络本体。

Critic 与配置

  • models/critic.py：Critic / VectorCritic 结构。
  • configs/alg/dime.yaml：critic 宽度、atoms、tau、utd 等核心超参。
  • configs/base.yaml：全局训练设置。
  • configs/sampler/dis.yaml：扩散 sampler 类型与参数。
  • configs/sampler/score_model/cond_pisgradnet.yaml：PISGRADNet 宽度与层数。

最短阅读路径建议

1. configs/base.yaml + configs/alg/dime.yaml 2. run_dime.py 3. diffusion/dime.py 4. diffusion/diffusion_policy.py 5. diffusion/od/dis.py + od_sampling.py + od_integrators.py 6. diffusion/common/models/pisgrad_net.py 7. models/critic.py
